# Sprint Execution Workflow

1. Start with sprint plan prompt and dependency order.
2. For `gpt-5.4` tickets, write planner handoff first.
3. Mark ticket `in-progress` when work starts.
4. Keep backend and frontend parallel only when contracts are explicit and shared in writing.
5. Move ticket to `qa-review` after implementation and local verification.
6. Record summary, QA result, release notes, DoD verification, and planner evidence at sprint end.
